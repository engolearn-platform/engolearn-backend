# M4 ? Screen Awareness
Status: implemented and scoped verification completed (2026-11-26); default-runtime quota blocker remains.

## Scope
Topic overview (published learner-visible metadata and item summaries) and learning positions CONTEXT, VOCAB, EXPRESSIONS for owned active attempts. Quiz and review, Speaking, Grammar and Assessment context are deferred. No DOM/screenshots, proactive inference, Topic LLM tool, cache or new collection.

## Architecture
- FE: page-driven registration through a Companion public capability, register/update/unregister from actual loaded page data, not route inference. Separate available context from attached draft snapshot; retain on navigation/minimize/expand, clear only accepted snapshot; retry same turn. One context per message.
- BE: optional typed reference on existing turn request; authenticated identity. A registry discovers Spring resolver strategies keyed by type, rejects duplicate registrations. Topic owns read-only contract, authorization, pinned version and stage selection. No cross-feature repositories; no internal HTTP. Context resolved before inference, not through a model tool. Independent tool registry also uses Spring-discovered handlers with duplicate-name detection; preserve tool definitions/order, validation, statuses, memory fences, timeout and accounting.
- Topic overview: titles, description, CEFR and published item titles/descriptions. Learning position: Topic overview, exactly one pinned item overview (title/description/scenario) and focused content typed by stage. Generic envelope, strongly typed payloads; Companion need not cast payload or inspect business fields. No JsonNode or raw entities in public contracts. JSON is serialized only at the Companion/model boundary.
- Reference: overview topicId; learning position attemptId, stage and itemIndex. Resolve against owned current-generation attempt, authoritative pinned content version and currently visible release, validate allowed position (including ordering). Never expose quiz keys, quick-check answers, unpublished or unauthorized content; only selected stage projection. Read-only narrow queries and batch publication check; do not load learner-wide catalog progress.
- Persist reference with accepted user message, load canonical reference on same-turn retry, do not replace from FE/new page. Reauthorize on retry. Historical messages without reference remain compatible; no full content persistence. Context is untrusted data, not instructions; bounded prompt size, unavailable outcome explicit. No new inference to resolve reference.

## Verification targets
Tool registry regression and duplicate-name startup guard; context ownership/version/reset/visibility/stage bounds; context omitted plain chat unchanged; accepted/rejected/retry attachment lifecycle; no quiz/answer leakage; real Gemini and browser E2E where environment permits; measure Topic read path and payload. Report actual coverage and remaining limitations.

## Implementation details and verification

- Spring-discovered `ScreenContextResolver<T>` strategies dispatch by `ScreenContextType`. The Topic contract returns a generic typed envelope and does its own projection, release visibility, attempt owner/generation and progression checks. New types require a strategy and typed request support, not a change to turn orchestration.
- Published overview returns at most 50 ordered item summaries and the visible count. Learning context includes only the selected stage and position plus parent overview, never quiz answers or quick-check answers. The initial serialized UTF-8 payload limit is 12,000 bytes (configurable via `engolearn.ai-companion.screen-context-max-bytes`); it is a byte bound, not an exact token budget.
- A failed resolution after admission retains the user message and its reference. Permanent failures require a new message; transient failures may retry the same turn. Content is not considered an instruction or memory evidence. Prompt isolation is defense in depth, not proof against model prompt injection.
- Tool registry refactor: 38 targeted regression tests passed. Combined Companion, TopicContextLookupIntegrationTest and ArchitectureTest: 78 passed, no skips/failures/errors. Real MongoDB test fixture measured six finds, no aggregation, 447 bytes serialized learning-position context. Normal attempt only; no production latency or retry-attempt query benchmark.
- Browser on default FE 3000/BE 8080 verified manual attachment, navigation retention and outgoing overview reference; quota admission rejected a fresh synthetic learner with 503 COMPANION_QUOTA_UNAVAILABLE. No default DB reset, policy override or inference bypass.
- Isolated FE 3001/BE 8082, existing smoke database plus a published sample: real Chrome and Gemini passed both overview and VOCAB turns; overview returned all five published lesson titles, vocabulary answer used the attached word despite navigation to a different stage. Accepted sends cleared the attached snapshot, updated availability was selectable, removal worked, unsupported quiz stage rejected before admission. The first isolated attempt encountered a CDP response-capture error; the corrected capture run passed. Synthetic conversations/memories were cleaned; test learner accounts and their own learning progress may remain.
- Full backend suite and browser coverage of every stage, transient retry, concurrent draft edits and responsive layouts are not established by these checks. Model grounding is a two-turn smoke, not a statistical evaluation.
- Frontend Topic regression suite: 31/33, with identical two failures reproduced on pre-M4 commit 84f90b7 (operation-count and schema-example mismatch). No unrelated repair in M4.
